## 1. 第一问：三层图样求解（精度与速度）

**前向模型。** 像素中心取 (u+0.5, v+0.5)。相机光线与三层屏幕分别求交，双线性采样各层相位 g_i，成像 I = sin²((π/2)·Σg_i)，与助教实现一致。

**求解流程。**
1. **初值（按深度分层的加权 SART，不使用 EyeReal 网络）**：
   - 用 Depth Anything V2 Small（Apache-2.0，公开预训练权重，未重新训练）估计两只眼图像的相对深度；
   - 前景按"与边框同色且与边框连通的区域为背景"分出，前景深度在每只眼内按 2%–98% 分位归一化到 [0,1]；
   - 按归一化深度给每个层像素算出归属权重：前景、中景、后景分别归 L1、L2、L3（三角形权重），背景归 L3；
   - 在两眼的光线上做 30 次加权 SART：每条光线的残差按归属权重（下限 ε=0.3）分给三层，而不是三等分。它给出的是双眼方程在 Σₖ gₖ²/wₖ 意义下的最小范数解，也就是"满足双眼"的那个分层解。
2. **逐例精修**：在上述精确前向上，用投影 Adam 直接优化三层图样（取值限制在 [0,1]）。目标是两只眼在助教掩码内的 MSE。迭代用 float32。融合后端用单应变换计算采样位置，以 float64 计算有效掩膜。
3. **按量化后的分数选点**：每 10 步把图样量化到 RGB8，再按对应求解器重渲染计分，保留最好的检查点。因此提交的 PNG 正是被选中、被计分的那一版。
4. **步数与学习率**：在自采的 lego 训练集上选参，调参子集 120 例，复核子集 136 例，大角度 val/test 只用来检查、不参与选择。
   - 30 步/lr 0.02 → 100 步/lr 0.08：复核子集均值从 48.1 dB 提高到 56.2 dB，每例只多约 0.2 s。
   - 200 步还能再高约 0.6 dB。本次取 100 步，是精度与速度的折中。
5. **速度**：
   - 融合 CUDA 算子：每一步只有两个内核，采样位置由单应变换现算，反向用 gather 精确转置，Adam 也在内核里完成。H100 上每步约 0.43 ms，原来的 PyTorch 实现约 3.4 ms。
   - 两个样例在两条 CUDA 流上重叠计算。
   - PNG 用自写的无损编码器（Up 滤波 + ISA-L deflate），每张约 15 ms，原来约 136 ms。
   - 读图与写图在线程池里进行，只输出必需文件。
   - test3 规模（1100 例）在 H100 上全流程约 200 s，最初版本为 1168 s。

## 2. 第二问：深度分层

**目标**（与助教确认）：画面的前景、中景、后景分别呈现在离观看者近、中、远的 L1、L2、L3 上，深度按相对值归一化。

**为什么普通求解分不出层。**
- 前向是相位叠加，没有遮挡，两只眼只约束两条视线上的相位和，存在大量"两眼看起来一样、分层完全不同"的等价解。
- 梯度下降时，同一条视线上三层像素的梯度完全相同，每次修正都等量反投到三层，所以三层会出现同一物体的"三份拷贝"。
- Adam 还会按像素归一化，把任何梯度加权都抵消掉。

**做法**：不改变两眼看到的图像，只改变修正量在三层之间的分配。
- 用相对深度给每个层像素算出归属权重（第 1 节第 1 步）；
- 用加权 SART 生成初值，使深度对应的那一层承担该处的相位；
- 再用 100 步 Adam 补回画质。

**测试前的评估**（lego 三维真值，按归一化深度计算"层内亮度与归属权重的相关"，0 为随机，1 为理想）：

| 方案 | 层内相关 | 第一问 PSNR 变化 |
|---|---:|---:|
| 原方案（网络初值 + Adam） | −0.04 | 0 |
| 本方案，单目估深，ε=0.3，100 步 | 约 0.14 | 约 −0.4 dB |
| 本方案，真值深度，ε=0.1，300 步（上限参照） | 0.46–0.63 | 约 0 |

- 在 test3 三分之一子集上：chair 第一问约 −1.0 dB，电影画面约 +0.5 dB。
- 目视：白背景主要落在 L3（暗的物体剪影），物体本身落在 L1、L2。
- 这是用一部分第一问画质换取分层的取舍。

## 3. 第三问：离轴建模

### 3.1 问题与约定
- **参考坐标系**：layer2（L2）。L2 中心为原点 O2，屏幕在 x=0 平面上，+x 指向观察者；屏宽 0.596736 m，1920×1080 像素。L1、L3 位于 x=±0.06 m。
- **相机约定与助教一致**：K 采用 right/down/forward，c2w 采用 right/up/back。像素 (u,v) 在相机系中的方向为 (x, y, z) = ((u+0.5−cx)/fx, −(v+0.5−cy)/fy, −1)，在世界系中的方向为 R_c2w·(x, y, z)。
- **约束**：
  - 观察者的眼睛位置（相机中心，即外参中的平移）不变；
  - 输入图像不变，不重新渲染；
  - 相机按离轴情况动态计算，每个样例、每只眼单独计算。

### 3.2 为什么原来的相机是"同轴"的，离轴应该是什么
输入相机是"对准 O2、水平视场 40°、主点在画面中心"的对称视锥，即同轴相机。在这种相机下：
- 屏幕只占画面的一部分（练习集平均约 58% 的像素有效）；
- 屏幕在画面里是一个随视角变化的梯形。

显示设备的离轴投影，即 Kooima 的广义透视投影（generalized perspective projection），是头部跟踪立体显示的标准做法。它的定义是：
- **投影面就是显示屏本身**：每只眼的视锥由眼睛到屏幕四角的连线确定；
- **视锥不对称**：眼睛不在屏幕中轴线上时，视锥左右、上下都不对称，这就是"离轴视锥"；
- **结果**：给这只眼的图像正好铺满屏幕，图像上的每个像素对应屏幕上的一个像素。

本题以 L2 为参考层，所以离轴相机的投影面取 L2。

### 3.3 L2 离轴相机的推导（本次使用的 `l2_camera`）
设某只眼的相机中心为 p = (p_x, p_y, p_z)，p_x > 0，即眼睛在屏幕前方。屏幕每米对应 s = W/屏宽 = 1920/0.596736 个像素。

**1. 投影面与 L2 重合。** 相机的三根轴与屏幕对齐：
- 右 = +y，对应屏幕像素 u 增大的方向；
- 上 = +z，对应 v 减小的方向；
- 后 = +x。

所以 R_c2w 的三列依次为 (0,1,0)、(0,0,1)、(1,0,0)，正交且行列式为 +1。

**2. 像素与 L2 像素一一对应。** 对 L2 上的点 (0, y, z)：
- 它在相机系中的坐标为 (y−p_y, z−p_z, −p_x)，深度为 p_x；
- 它在 L2 面板上的像素坐标为 u = s·y + W/2，v = −s·z + H/2。

令相机投影等于面板坐标，得到

  f_x = f_y = s·p_x，  c_x = W/2 + s·p_y，  c_y = H/2 − s·p_z

即 **K = [[s·p_x, 0, W/2+s·p_y], [0, s·p_x, H/2−s·p_z], [0, 0, 1]]**。

- `pose` 的平移就是原来的眼睛位置，旋转是上面的屏幕对齐旋转；
- 焦距等于"眼到 L2 的距离"乘以 s；
- 主点是眼睛在 L2 上垂足所在的像素，它的偏移量就是离轴量。

**3. 动态性。**
- 眼睛越远，f 越大；
- 眼睛偏离屏幕中心越多，主点越偏，可以落到画面以外，这正是强离轴视锥；
- 眼睛正对屏幕中心时，主点在画面中心，视锥对称。

**4. 练习集 100 例（200 只眼）上的数值。**
- f 的范围是 1848–4403，中位数 3262；
- c_x 的范围是 −923 到 2862，c_y 的范围是 −180 到 900；
- 39% 的眼睛主点落在画面外。

**5. 核对。**
- 取一份只在 L2 上有图案的图样，按上述相机用助教 v3 的 `forward_render(…, K_l, K_r)` 渲染。眼图像素 (u,v) 与 sin²(π/2·L2(u,v)) 逐像素一致，误差 3e-8，说明"像素 ↔ L2 像素"的映射完全成立。
- 在离轴相机下，我们的 GPU 渲染器与助教前向也一致。

**6. 为什么不只改 K、保留原来的旋转。**
- 原相机朝向 O2，成像面与 L2 不平行，所以 L2 到成像面的映射是一个含透视项的单应。助教格式中 K 的最后一行固定为 [0,0,1]，表示不了透视项。
- 因此"保持朝向、只改 K"的模型只能近似离轴视锥，我们比较过两类：
  - 平移主点，双眼共用；
  - 每只眼按 L2 投影的包围框拟合非对称视锥，也就是 fx≠fy 的非方形像素。
- 它们都做不到"投影面与屏幕重合"。

### 3.4 为什么选 Kooima：复用原图时双眼仍然一致
助教规定离轴时**输入图像不变、不重新渲染**。这意味着同一对图像要按新的相机重新解释。

**对照实验**：lego 30 例，同一个求解器，目标图分别取"复用的原图"和"按该离轴相机真实渲染的图"：

| 离轴相机 | 目标：复用原图 | 目标：真实渲染 |
|---|---:|---:|
| **Kooima（L2 投影面）** | **51.4 dB** | 51.8 dB |
| 保持朝向、包围框非方形 K | 38.2 dB | 52.3 dB |

**解释**：
- Kooima 下两只眼共用同一个投影面（L2）、同一种像素与屏幕的对应关系，所以把原图解释为"铺满屏幕的双眼图像"后，双眼之间依然几何一致。复用原图几乎无损，只比真实渲染低 0.4 dB。
- 保持朝向的模型给两只眼不同的、非方形的 K。复用原图等于把两张图各自拉伸，这对图像不再对应任何真实场景，三层屏无法同时满足两只眼，损失约 14 dB。

这是选择 Kooima 的主要物理依据：它是显示领域标准的离轴投影，而且在"复用原图"这一规则下仍然自洽。

### 3.5 离轴下的求解
- **目标**：同一对输入图像，在 L2 相机下被解释为"铺满屏幕、分别给两只眼看的图像"。三层图样必须按新的光线重新求解。有效像素比例从约 58% 提高到约 87%。
- **初值**：用无训练的偏振场层析（SART）。
  - 前向 I = sin²(π/2·Σgₖ) 对每条光线取 a = (2/π)·arcsin√I，问题就线性化为 Σgₖ = a。
  - 在 L2 相机的光线上做 30 次 SART，适用于任意相机，不依赖只在同轴相机下训练过的网络。
- **精修**：在 L2 相机的光线上用投影 Adam 精修 100 步（lr 0.08），按量化到 RGB8 后的分数选检查点。SART 和 Adam 都用与第一问相同的融合 CUDA 算子。
- **结果**：
  - 练习集 100 例（H100）：离轴分支平均 **51.83 dB**，以 L2 相机计分，目标为复用的原图；第一问分支 56.96 dB。
  - 本次运行的离轴分支自测分数见第 0 节。
- **剩余误差的来源**：铺满屏幕的视锥要求像素级显示，没有分辨率余量；同时 L1/L3 的视差要覆盖整幅屏幕。

### 3.6 局限
- **朝向**：离轴相机的朝向与输入位姿不同。我们把"外参不变"理解为眼睛位置（相机中心）不变；朝向属于离轴投影的定义，因为在 Kooima 投影中，屏幕对齐的旋转是投影矩阵的一部分。在助教格式下（K 最后一行固定为 [0,0,1]），只有这样才能让投影面与 L2 重合。
- **可辨识性**：由显示几何不能唯一反推人眼的物理内参。这里给出的是以 L2 为投影面的标准离轴投影。
- **未建模的光学效应**：液晶斜入射的光学效应（偏振、视角相关的透过率）不在助教前向模型内，没有建模。
