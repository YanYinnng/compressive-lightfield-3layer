离轴建模，到底在建什么模

一个眼睛位置，一张不变的输入图，四种都说得通的相机。下面用一张可拖动的图，把"离轴"拆成几个能看见的问题。

先给五个短答案

Q1离轴要解决什么问题？

普通任务里，每只眼被当成"对准屏幕中心、水平视场 40°、画面居中"的相机，屏幕只占画面的一部分，斜看时还是个梯形。头部跟踪显示的做法不同：眼睛透过屏幕这扇"窗"看内容，画面应该正好铺在这扇窗上，眼睛偏到哪里，视锥就跟着歪到哪里。离轴任务要你把同一对输入图重新理解成"透过屏幕看到的画面"，再为它求三层图样。

看交互图
Q2我到底在建什么模？

建每只眼的相机：眼睛在哪（位置），以及画面上每个像素对应哪条视线（由朝向 R 和内参 K 共同决定）。目标图不变，所以这张"像素→视线"对应表一换，每个像素的颜色要从屏幕上哪一点发出来，也就跟着换了。

相机拆开看
Q3为什么有不同建法？

题目只给了眼睛位置和目标图，没规定这张对应表。可以保持朝向只挪主点，可以保持朝向把画框缩放到正好框住屏幕，也可以把成像面转到和屏幕平行。三种都合理，但给出的目标光场不同，只有和评测方用的那一种一致才能得分。

四种建法对比
Q4只改内参，是不是位置和朝向都不动？

是。K 只能在原来那块成像面上平移、缩放坐标，成像面的朝向由 R 决定。要让成像面和屏幕平行，必须改 R，只改 K 做不到。我最后用的屏幕平面相机改了朝向，但眼睛位置没动。

Q5测评和非离轴有什么区别？

目标图完全一样，都是那对左右眼图，不重新渲染。区别只在用哪台相机把三层图样"看"成眼图：普通情况用标准相机，离轴情况用离轴相机。你声明的相机要和评测方的一致，不一致时求解得再好也只有 13–17 dB。

测评流程对比

先把"相机"拆开：位置 + 像素到视线的对应

在这道题里，相机不是用来拍照的，而是一张对应表：从眼睛出发，画面上的像素 (u, v) 对应哪一条视线。助教代码里的写法是：

视线方向 d(u, v) = R · ( (u − cx)/fx , −(v − cy)/fy , −1 ) 起点 = 眼睛位置 C K = [[fx, 0, cx], [0, fy, cy], [0, 0, 1]] fx, fy：焦距（像素） cx, cy：主点 R = 相机的 右 / 上 / 后 三个轴（世界坐标） 视线朝向"后"的反方向

这张表由三部分决定：

位置 C：眼睛在哪。题目给定，不能动。
朝向 R：成像面朝哪个方向摆。
内参 K：在这块成像面上，像素坐标怎么排布：主点 (cx, cy) 是光轴穿过画面的那个像素，焦距决定一个像素占多大角度。

渲染一只眼的眼图时，每个像素沿自己的视线依次穿过 L1、L2、L3，把三层的相位加起来，再算 sin²。所以换相机 = 换"哪个像素看哪条视线"。眼睛位置不变时，从眼睛发出的视线集合其实一条都没变，变的只是每条视线被记在哪个像素上。

普通任务的标准相机：fx = fy = 1920 / (2·tan20°) ≈ 2637.6，主点在画面中心 (960, 540)，R 让相机正对屏幕中心 O2、不滚转。

四种建法，各自在做什么

四种建法的眼睛位置完全一样，区别只在"像素→视线"的对应。切换上面的建法按钮，对照着看：

　标准相机（普通任务）

看向屏幕中心，视场 40°，主点居中。把"偏右斜看"和"远处、偏左、偏高"两个预设各点一下：图 B 里屏幕变成偏到一边的梯形，只占画面的一部分；图 C 里画面铺到屏幕外面很大一片。练习集平均只有约 58% 的像素能落在三层屏幕上。

　主点平移（我 11-07 的第一版）

朝向和焦距都不动，只把主点挪一下，让屏幕在画面里居中；两只眼取同一个平移量。它只是把画框整体挪了挪，屏幕在画面里的大小和梯形形状都不变，有效像素和标准相机差不多。官方离轴得分 5/20。

　包围框

朝向不动，同时调焦距和主点，让画框正好框住 L2 的外接矩形。fx 和 fy 不再相等，像素变成长方形。图 B 里屏幕顶到了画框四边，但还是梯形；图 C 里贴到屏幕上的网格仍然是透视变形的。官方离轴约 15 dB。

　屏幕平面相机（Kooima，最终方案）

把成像面转到和屏幕平行，再让画面正好等于 L2 屏幕。图 B 里 L2 的四边形和画框完全重合；图 C 里网格横平竖直，正好铺满屏幕：画面上的像素 (u, v) 就落在屏幕的像素 (u, v) 上。推导只要两步：

眼睛位置 p = (pₓ, p_y, p_z)，屏幕每米像素数 s = 1920 / 0.596736 ≈ 3217.5 主点 = 眼睛在 L2 上的垂足 (0, p_y, p_z) 对应的屏幕像素： cx = 960 + s·p_y， cy = 540 − s·p_z 焦距 = 眼睛到 L2 的垂直距离 × s： fx = fy = s·pₓ 朝向：右 = +y，上 = +z，后 = +x（成像面平行于屏幕）

主点偏离画面中心多少，就是"离轴"了多少。把眼睛拖到屏幕边缘以外（比如"远处、偏左、偏高"），主点会跑到画面外面，练习集里约 39% 的眼睛是这样。这在头部跟踪显示里是正常现象，叫离轴视锥：视锥由眼睛到屏幕四个角的连线决定，左右、上下都不对称。

为什么"只改 K"做不到贴合屏幕

一句话版本：K 只能在成像面上做平移和缩放，决定"梯形还是矩形"的那一项根本不经过 K，只由朝向 R 决定。下面分四步把这件事算出来。

第 1 步：投影写成两段

为了少写负号，把相机坐标写成"右 / 下 / 前"三个轴，记作 r、d、f（都是世界坐标里的单位向量，f 指向眼睛前方）。一个世界点 X 在相机里的坐标是

x = r·(X − C) y = d·(X − C) z = f·(X − C) （z 是深度，在眼前方时 z > 0）

投影分两段。先除以深度，得到归一化坐标；再用 K 换算成像素：

第一段（只和 R、C 有关）： x̂ = x / z , ŷ = y / z 第二段（只和 K 有关）： u = fx·x̂ + cx , v = fy·ŷ + cy 写成矩阵： λ·[u, v, 1]ᵀ = K·[x, y, z]ᵀ , K = [[fx, 0, cx], [0, fy, cy], [0, 0, 1]]

K 的第三行是 [0, 0, 1]，所以 λ = z：K 碰不到"除以深度"这一步。第二段对 (x̂, ŷ) 只是横向乘 fx、纵向乘 fy、再加一个平移。这类变换把直线变成直线、平行线仍然平行、矩形仍是矩形、梯形仍是梯形。

第 2 步：屏幕上的点投到成像面上

L2 上的点写成 X = (0, s, t)，s 是屏幕上的横坐标（向右），t 是纵坐标（向上），单位米。代入第 1 步，深度是

z(s, t) = f·(X − C) = f_y·s + f_z·t − f·C

其中 f_y、f_z 是前向 f 在世界 y、z 方向上的分量。x、y 也都是 s、t 的一次式。所以从屏幕坐标到归一化坐标是一个分式：

x̂ = (a₁ s + b₁ t + c₁) / (f_y s + f_z t − f·C) ŷ = (a₂ s + b₂ t + c₂) / (f_y s + f_z t − f·C) 矩阵形式： λ·[x̂, ŷ, 1]ᵀ = G·[s, t, 1]ᵀ , G 的第三行 = (f_y, f_z, −f·C)

这就是一个单应（透视变换）。分母随 s、t 变化，意思是屏幕上不同位置离眼睛的深度不同：近的一侧放大，远的一侧缩小，屏幕上本来平行的上下两条边投过来会向远处汇聚。这就是梯形的来源。

第 3 步：K 改不了 G 的第三行

把两段连起来，从屏幕坐标到画面像素是

λ·[u, v, 1]ᵀ = K·G·[s, t, 1]ᵀ

K 的第三行是 [0, 0, 1]，所以 K·G 的第三行就等于 G 的第三行 (f_y, f_z, −f·C)，和 K 取什么值完全无关。画面上的网格要和屏幕网格一一对应，即 (u, v) 是 (s, t) 的一次函数、没有分母变化，就必须让这一行变成 (0, 0, 常数)：

f_y = 0 且 f_z = 0 ⟺ 前向 f 平行于世界 x 轴 ⟺ 成像面平行于屏幕

f 是 R 的一部分。所以能不能贴合屏幕，只取决于朝向；K 再怎么调，都只是在梯形上做平移和缩放。主点平移只动 cx、cy，包围框同时动 fx、fy、cx、cy，两者都没碰 f，所以在图 C 里网格总是歪的。

数值例子（标准相机，左眼）：眼睛 1.0 m 正对屏幕时，f = (−0.9996, 0.030, 0)，f_y 不为 0 是因为每只眼都向 O2 内收了 1.7°；偏右 25°、仰 5° 时，f = (−0.915, −0.394, −0.087)，透视项大得多。即使允许任意仿射（比 K 还自由），把斜看时的梯形四角拉到画框四角，也仍差 50–70 像素；正对时也差约 5 像素。

第 4 步：转到屏幕方向后，K 正好就是屏幕平面相机

令前向 f = −x（正对屏幕看）、右 r = +y、下 d = −z。眼睛在 C = (Cₓ, C_y, C_z)，深度处处等于 Cₓ，分母不再变化：

u = fx·(s − C_y)/Cₓ + cx 希望等于屏幕像素 S·s + 960 v = fy·(C_z − t)/Cₓ + cy 希望等于屏幕像素 540 − S·t （S = 1920 / 0.596736 ≈ 3217.5 像素/米） 对比系数： fx = fy = S·Cₓ , cx = 960 + S·C_y , cy = 540 − S·C_z

这正是上面"屏幕平面相机"那组公式。所以完整的说法是：先用 R 把成像面转到和屏幕平行，消掉透视项；剩下的平移、缩放再交给 K。

换个角度看，眼睛不动、只转成像面时，同一条视线在新旧两块成像面上的像素之间，正好差一个单应 H = K′·R′ᵀ·R·K⁻¹。它的第三行一般不是 [0, 0, 1]，所以没法塞进 K，只能写进 R。

所以回答 Q4：只改内参，眼睛位置和朝向都不动。屏幕平面相机动了朝向，但眼睛位置不动；而眼睛不动时，视线集合不变，转动成像面只是换了一种给视线编号的方式。我把题目说的"外参不变"理解为"眼睛位置不变"。助教的提交接口里本来就要求交 pose_l、pose_r，模板注释写的是 "L2 camera calculation"，11:40 那次用这个模型拿到了离轴满分。

为什么屏幕平面相机复用原图也没问题

输入图是按标准相机渲染的。离轴分支直接把它当成离轴相机的画面，必然有偏差。偏差大不大，要看两只眼"重新解释"之后还能不能对应同一个三维场景。lego 30 例的对照：

离轴相机目标：复用原图（题目规定）目标：按该相机重新渲染
屏幕平面相机51.451.8
包围框38.252.3

两种相机在物理上都能做到约 52 dB；差别只在复用原图之后。屏幕平面相机下，两只眼共用同一块成像面（L2）、同一个像素尺度，把原图贴到屏幕上后，左右两张图仍然近似是一对一致的双眼图，所以几乎不掉分。包围框给两只眼各自一套不同的长方形像素，相当于把两张图各自拉伸，拉伸后的这对图不再对应任何真实场景，三层屏没法同时满足两只眼。

这也说明"复用原图、不重新渲染"这条规则，和屏幕平面相机是配套的。

一句话串起来

离轴建模是在回答：眼睛不动、图不变，这张图的每个像素该由屏幕上哪一点来显示。答案就是每只眼的相机。题目没把它唯一定死，所以有不同建法；评测方用了其中一种，声明的相机对上了才得分。我最后用的是"成像面贴在 L2 屏幕上"的相机：画面像素和屏幕像素一一对应，主点就是眼睛在屏幕上的垂足。

图中所有几何都按助教 v3 的约定计算，并已与我的 Python 实现和助教的 render_numpy 核对：四种建法的 K 和 R 一致到 1e-12，有效像素比例差小于 0.3%（页面用网格采样估算），屏幕平面相机下"画面像素 = 屏幕像素"的误差小于 1e-12 像素。官方分数：主点平移 5/20（11-07 练习），包围框约 15 dB（test2），屏幕平面相机 20/20（11-08 11:40）。
